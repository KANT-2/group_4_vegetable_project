# 쿠폰 발급과 장바구니 쿠폰함

2026-10-13 · A 조영우

## 구현

- 프로모션 배너 아래의 별도 혜택 보기·배송 안내 보기·체험 안내 보기 버튼을 제거했습니다. 동일한 배너와 페이지 내 메뉴는 유지합니다.
- 쿠폰 혜택 카드에 실제 쿠폰 받기 버튼을 추가했습니다. 로그인 전에는 같은 행사로 복귀하는 로그인 화면으로 이동합니다.
- Server Action에서 허용한 행사 ID를 검증하고 실제 세션을 확인합니다. 사용자 ID·할인액·만료일을 클라이언트에서 받지 않습니다.
- `claim_coupon` DB 함수가 발급 기간·오픈런 시간·첫 구매 이력·중복을 검증하고 본인 쿠폰을 저장합니다.
- 장바구니·찜 메뉴에 내 쿠폰 탭(`/cart?tab=coupons`)을 추가했습니다. 받은 쿠폰의 할인값·최소금액·한도·대상·만료시간·상태를 확인합니다.
- 조회는 RLS와 계정 확인을 적용합니다. 쿠폰 테이블의 직접 insert/update/delete 권한은 열지 않습니다.

## 조건

| 쿠폰    | 발급 조건                                        | 보관 기한                   |
| ------- | ------------------------------------------------ | --------------------------- |
| 오픈런  | 한국 시간 매일 07:00 이상·11:00 미만, 하루 한 번 | 발급 당일 종료까지          |
| 첫 구매 | 결제 완료 이력이 없는 회원, 회원당 한 번         | 발급 후 7일, 행사 종료 이내 |
| 김장    | 로그인 회원, 회원당 한 번                        | 2026-11-30 종료까지         |

전체 행사 기간은 2026-10-13부터 2026-11-30까지입니다. 재요청은 기존 발급 ID를 반환하므로 쿠폰이 중복되지 않습니다. 김장 대상은 양배추가 아닌 배추(`napa-cabbage`)·무·양파입니다.

## 공유 DB 적용

추가 파일: `supabase/migrations/202610130001_coupon_wallet.sql`.

기존 주문 테이블을 사용합니다. 공유 DB의 기존 migration을 유지한 상태에서 새 파일만 적용합니다. 실행 전 `coupon_campaigns`, `user_coupons`, `claim_coupon(text)`가 없는지 확인합니다. 적용은 트랜잭션으로 처리하며 기존 상품·주문·장바구니를 변경하지 않습니다. CLI로 기존 DB를 reset하지 않습니다.

**2026-10-13 공유 `vegetable` DB 적용 완료.** 기존 쿠폰 테이블·함수가 없는 것을 먼저 확인한 뒤 SQL Editor에서 migration을 적용했습니다. RLS 활성화, authenticated 발급 허용, anon 발급 불가, 쿠폰 테이블 직접 insert/update 불가를 조회했습니다. 실제 DB에서 기존 계정의 발급·동일 쿠폰 재요청·본인 조회·다른 계정 조회 차단을 트랜잭션으로 검증한 뒤 rollback했으며 테스트 쿠폰은 남기지 않았습니다. 쿠폰 조회 실패는 받은 쿠폰 없음으로 숨기지 않습니다.

SQL Editor 실행은 CLI migration 이력에 자동 등록되지 않습니다. 실제 적용 시 실행 일시와 확인 결과를 이 문서 및 DB 기록에 남깁니다.

## 검증

PostgreSQL 테스트 엔진에서 비로그인 발급 차단, 본인 발급·중복 재요청, 다른 계정 조회 차단, 직접 쓰기·만료일 변조 차단, 첫 구매 조건, 없는 행사·종료 행사 거부, 오픈런 시간 조건을 검증했습니다. 전체 기존 테스트와 타입 검사도 통과했습니다.

## 범위

이번 작업은 발급·보관·조회입니다. 결제 화면에서 쿠폰을 선택해 주문 금액을 할인하거나 사용 처리하는 기능은 아직 연결하지 않았습니다. 기존 결제 금액을 클라이언트에서 임의로 차감하지 않습니다. 쿠폰 사용 기능을 추가할 때 주문 함수의 조건·한도·중복·소진을 같은 트랜잭션에서 검증해야 합니다.
