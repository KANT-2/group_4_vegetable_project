# C #13 마이페이지·프로필 조회·수정

작업일: 2026-10-12 / 담당: C 이상재.

## 구현

- `/mypage`에서 로그인 이메일과 본인 닉네임을 조회합니다. 비로그인 접근은 `/login?next=/mypage`로 이동합니다.
- 기존 `getProfile`·`updateProfile`·Zod 규칙을 재사용합니다. 닉네임은 앞뒤 공백 제거 후 2~20자이며 다른 필드는 수정할 수 없습니다.
- 저장 중 입력·버튼 비활성화, 공백·길이 오류, 서버 저장 오류, 저장 완료 안내와 프로필 조회 실패 재시도를 제공합니다.
- 저장 성공 후 헤더 닉네임도 새로 조회합니다. 현재 닉네임과 같으면 저장 버튼을 비활성화합니다.
- DB 수정 ID는 서버 인증 사용자로 결정합니다. 화면의 계정 ID는 일치 여부만 검사하며, 계정이 바뀐 오래된 화면의 저장 요청은 DB 변경 전에 거부합니다. RLS로 타인 프로필 조회·수정도 차단합니다.
- 계정 확인이 끝나기 전이나 계정이 달라졌을 때 이전 프로필 표시를 숨깁니다.
- A의 디자인 토큰·공통 입력·버튼을 사용합니다. 모바일 입력은 `inputMode=text`, `autoComplete=nickname`, `autoCapitalize=none`, `autoCorrect=off`, `spellCheck=false`입니다.
- 기본 배송지 한 곳의 받는 분·연락처·우편번호·기본 주소·상세주소를 저장·삭제합니다. 연락처는 공백·하이픈을 제거하고, 우편번호는 숫자 5자리입니다. 주소 항목에는 shipping 자동완성 속성을 지정했습니다.
- Google 로그인 계정의 비밀번호는 Google에서 관리합니다. 마이페이지에 Google 계정 보안 관리 링크를 제공합니다. 앱에 Google 비밀번호를 입력하거나 저장하지 않습니다.
- 배송지 저장에는 `202610120001_profile_shipping.sql`이 필요합니다. 2026-10-12 공용 vegetable DB에 적용하고 컬럼 5개·수정 권한을 확인했습니다. 기존 본인 전용 RLS를 유지하며 기본 배송지 수정은 기존 orders를 변경하지 않습니다. 주문 화면의 기본 배송지 자동 입력은 주문 기능 구현 시 연결합니다.

## 검증

- 실제 Google 계정으로 로그인 후 본인 프로필 조회, 닉네임 변경·공백 제거·저장 중 비활성·성공 안내·헤더 갱신을 확인했습니다.
- 실제 DB 저장 후 새로고침에도 닉네임이 유지됐습니다. 검증용 닉네임은 기존 값으로 복구했습니다.
- 공백 입력 오류 안내와 비로그인 개인 경로 차단을 실제 화면·HTTP에서 확인했습니다.
- 공용 DB에 가상 배송지를 저장하고 새로고침 후 유지되는 것을 확인했습니다. 사용자 승인 후 테스트 배송지를 삭제했고 새로고침 후 빈 배송지와 기존 닉네임이 유지되는 것을 확인했습니다. 실제 배송 정보는 입력하지 않았습니다.
- 테스트 22개 통과: 계정 변경 요청·ID 주입·DB 저장 실패 처리, 기본 배송지 검증·본인 저장/조회/삭제·타인 접근 차단·비로그인 차단 포함.
- 타입·lint·포맷·Mock 본문 모드 빌드 통과. 인증과 프로필은 실제 Supabase를 사용합니다.
- 360px 모바일에서 입력·저장 버튼·이메일 줄바꿈과 가로 넘침 없는 표시를 확인했습니다. 물리 휴대폰 키보드와 자동완성 동작은 팀원 기기에서 추가 확인합니다.

## 실행

`.env.local`의 Supabase URL·공개 키와 `NEXT_PUBLIC_SITE_URL`을 설정합니다. 기본 로컬 접속은 `http://localhost:3000`입니다. 브라우저 접속 호스트·포트와 환경변수를 일치시켜 주세요.

3103 검증 환경은 `USE_MOCK_DATA=true`, `NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3103`으로 빌드·실행했습니다. Next.js 개발 리소스의 origin 제한 때문에 이 주소의 브라우저 확인은 production 실행으로 진행했습니다.
