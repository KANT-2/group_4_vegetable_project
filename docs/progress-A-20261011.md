## 팀원이 실행하는 방법

```text
npm ci
npm run dev
npm test
npm run build
```

환경변수가 없거나 `USE_MOCK_DATA=true`이면 공식 레시피는 저장된 JSON으로, 판매 상품·농가는 B의 시연용 데이터로 표시한다. DB 오류를 시연 데이터로 숨기지는 않는다.

자료를 다시 반영할 때:

```text
node scripts/export-app-recipes.mjs
```

공용 Supabase에는 기존 생성 migration을 다시 실행하거나 reset하지 않는다. 현재의 9개 공통 테이블이 적용된 DB에서 아래 두 파일만 순서대로 검토·적용한다.

1. `supabase/migrations/202610110001_verified_recipe_metadata.sql`
2. `supabase/seeds/verified-recipes.sql`

첫 파일은 migration이라 한 번만 적용한다. seed는 재실행할 수 있지만 해당 공식 레시피와 판매 상품 연결을 현재 활성 상품에 맞춰 갱신한다. 운영 앱은 `public.recipes`를 읽으므로 별도 검토용 `food_catalog` 스키마를 공개할 필요가 없다.
