# 마이페이지·주문/결제 디자인 리뉴얼

2026-10-13 · A 조영우 · 디자인 및 프런트엔드

## 화면 변경

- 마켓컬리 마이페이지의 회원 요약, 쇼핑 메뉴, 본문 구역을 참고해 PC는 좌측 메뉴와 우측 내용으로 구성했습니다. 모바일은 간결한 회원 요약과 2열 메뉴 아래에 회원 정보·배송지를 표시합니다.
- 회원 정보, 기본 배송지, Google 보안 안내를 각각 분리했습니다. 실제 제공하는 주문내역·환불, 회원 정보·배송지, 장바구니·찜 메뉴만 연결했습니다. 가상의 적립금·등급·쿠폰은 추가하지 않았습니다.
- 주문/결제는 상품 사진·수량·가격 → 배송 정보 → 결제 수단 순서로 구성했습니다. PC 오른쪽 총액 요약은 스크롤 중 유지되고 모바일에서는 입력 영역 다음에 표시됩니다.
- 결제 요약에서 정가 합계, 상품 할인, 배송비, 최종 금액을 구분하고 주문 버튼에 총액을 표시합니다. 20,000원 무료배송 기준은 기존 계산 함수를 그대로 사용합니다.
- 기존 테라코타 `#B4541F`, 짙은 갈색 `#7A3A12`, 브랜드 연한 배경·흰색·회색 토큰을 사용했습니다. 컬리의 보라색이나 로고·이미지·멤버십 기능을 복사하지 않았습니다.

참고한 화면: [마켓컬리](https://www.kurly.com/main)의 로그인된 마이컬리 메뉴·회원 요약·주문내역 화면. 실제 컬리 주문을 생성하거나 결제를 진행하지 않았으며, 결제 레이아웃은 기존 못난이마켓 기능에 맞춰 구성했습니다.

## 기능 보존

Supabase 인증, 사용자 ID 검증, 닉네임·배송지 Zod 검사, 프로필 저장·배송지 삭제 확인, 모의 결제 요청 키·중복 요청 방지·실패 재시도·주문 상세 이동을 보존했습니다. 결제 금액 계산·DB·RPC·권한·서버 액션은 변경하지 않았습니다. 실제 청구가 없는 모의 결제임을 결제 수단 아래에 표시합니다. 상세주소는 기존 스키마대로 선택 입력입니다.

`ProfileForm`은 계정 확인을 담당하고 `ProfileEditor`는 편집 화면을 담당합니다. 실제 `/mypage`는 기존 `requireUser` 및 클라이언트 계정 검증을 거쳐 편집 화면을 렌더합니다. 인증을 우회하는 배포 경로나 테스트용 로그인 기능은 추가하지 않았습니다.

## 검증과 한계

- 기존 자동 테스트 53개, lint, typecheck, production build 통과.
- PC 1280px, 모바일 390px·320px의 회원/주문 화면에서 가로 넘침 없음 확인.
- 닉네임 1자 입력, 잘못된 우편번호 입력 시 기존 Zod 안내 표시 확인. 회원 배송지와 주문 배송지 모두 확인.
- 결제 수단 선택, 상품 이미지 로드, 29,400원 정가 − 10,700원 할인 + 3,500원 배송비 = 22,200원 표시 확인.
- 로컬에는 Supabase 환경설정이 없어, 임시 개발 전용 화면에서 **실제 편집·결제 컴포넌트에 가상 데이터**를 넣어 UI를 검수했습니다. 실제 프로필 저장·주문 성공·공유 DB·실기기 검수 완료를 의미하지 않습니다.
- 임시 검수 페이지는 제거했고 최종 빌드에 포함되지 않습니다. 실제 마이페이지 비로그인 접근의 로그인 이동도 확인했습니다.
