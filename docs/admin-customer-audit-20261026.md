# 관리자 → 고객 화면 반영 점검 (2026-10-26)

## 점검 범위와 방법

현재 로컬 작업 트리를 대상으로 관리자 인증 후 저장 API를 호출하고, 고객 목록·상세·메인 페이지의 HTTP 응답과 404 상태를 확인했다. 임시 데이터를 등록·수정·삭제·복원한 뒤 기존 서버 파일 데이터를 복구했다. 점검용 데이터가 남지 않은 것도 확인했다. 실제 브라우저 두 창에서 클릭·자동 갱신 시간을 측정하는 검사는 실시하지 않았다.

현재 연동은 `var/managed-content/catalog.json` 기반이며 FastAPI catalog·공유 DB 연동 완료를 뜻하지 않는다. 아래 연결 변경은 현재 미커밋 상태다.

## 고객 화면 반영 확인

| 항목 | 확인 결과 |
| --- | --- |
| 기존 상품명·가격 수정 | 검색 목록·상세·메인 진열 상품에 반영 확인 |
| 재고 0개·품절 | 고객 목록·메인·상세 공개 유지와 품절 문구 확인. 구매 차단은 기존 서버 Action에 구현되어 있음 |
| 신규 상품 | 검색 목록·상세에서 노출 확인. 메인 진열은 추천·할인·제철 등의 별도 선정 조건을 따름 |
| 상품 판매 중지·삭제·복원 | 고객 상세 404 및 복원 후 200 확인 |
| 레시피 수정 | 목록·상세의 내용·메인 진열 레시피 반영 확인 |
| 레시피 등록·삭제·복원 | 새 상세 200, 삭제 404, 복원 200 확인 |
| 농가 소개 수정·등록 | 이야기 목록 및 상세의 소개·본문 반영, 신규 농가 상세 200 확인 |
| 농가 삭제·복원 | 상세 404 및 복원 후 200 확인 |
| 혜택·이벤트 수정·등록 | 목록·상세 반영 확인. 메인 배너는 별도 반복 점검에서 변경된 제목·분류·이미지 속성의 응답 반영 확인 |
| 이벤트 비공개·삭제·복원 | 비공개/삭제 상세 404, 복원 200 확인 |
| 자동 갱신 | 3초 버전 확인 및 창 포커스 시 재조회 코드 존재. 브라우저 실측은 미실시 |

## 남은 문제와 연결 경계

1. **FastAPI/공유 DB 미연결 — 최우선**
   - 관리자 수정은 서버 파일에 저장되고 기존 Supabase 상품 원본은 바뀌지 않는다.
   - 실제 계정의 장바구니·찜 조회는 `src/services/cart.ts`에서 Supabase 상품을 직접 읽는다. 관리자 파일의 가격과 DB 가격이 달라질 수 있다.
   - 기존 모의 결제는 `src/actions/checkout.ts`의 Supabase RPC로 DB 가격을 계산한다. 새로운 FastAPI 주문 코드가 동일한 파일 수정값을 읽는 구조가 아니다.
   - 현재 품절 차단은 수정한 Next 서버 Action 기준이다. 영우 담당 FastAPI 주문 API의 재고·품절 판정은 별도 합의·구현이 필요하다.

2. **신규 상품의 농가·채소 연결 누락**
   - `AdminProducts.tsx` 신규 등록은 `farmName: ""`, `vegetableId: ""`를 저장한다.
   - 상품 자체의 목록·상세는 열리지만 농가별 상품·채소별 관련 레시피 연결은 완전하지 않다.
   - 기존 상품과 같은 농가/채소 선택 및 유효한 참조를 등록 과정에 추가해야 한다.

3. **농가 이름 변경 후 기존 상품 링크 불일치**
   - 변경된 농가 이름의 상세 URL은 정상이다.
   - 기존 상품의 `farmName`은 자동 변경되지 않는다. 점검 중 이전 농가 URL이 404가 되는 것을 확인했다.
   - 농가를 이름이 아닌 고정 ID로 참조하거나 이름 변경에 따른 연결·이전 URL 처리가 필요하다.

4. **이벤트 수정 후 상세 화면/기능 차이**
   - 수정된 이벤트 상세는 기존 전용 페이지 대신 `PromotionPreview` 공통 화면으로 표시된다.
   - 내용은 반영되지만 원래 전용 화면의 쿠폰 발급 등 기능이 그대로 유지되지는 않는다.
   - 이벤트 안내 금액·조건 수정은 실제 `coupon_campaigns`의 쿠폰 정책 변경과 연결되지 않는다.

5. **메인 화면의 고정 문구와 이미지 속 글자**
   - 메인 배너의 데이터 속성은 연결되어 있지만 이미지에 그려진 글자를 제목 수정으로 바꿀 수는 없다.
   - 선별 기준·쉬운 집밥 등 일부 띠 배너 문구와 고정 소개는 관리자 편집 필드가 없다. 레시피 수 같은 동적 값은 조회 결과를 따른다.
   - 신규 등록이 모든 메인 진열에 무조건 추가되는 것은 아니며 추천·분류·표시 개수 조건을 따른다.

6. **저장 성공 안내 시점**
   - 일부 관리 화면은 서버 응답을 기다리지 않고 수정 완료 안내와 창 닫기를 수행한다.
   - 저장 실패·동시 수정 409는 전역 오류로 표시되지만 완료 안내가 먼저 보일 수 있다. 저장 완료를 기다리도록 개선할 필요가 있다.

7. **실행 환경·전달 상태**
   - 같은 서버의 파일을 읽는 브라우저끼리 연결된다. 다른 팀원 로컬 PC와 데이터가 자동 공유되지 않는다.
   - 단일 서버 재시작 후 파일은 유지되지만 서버리스·복수 인스턴스는 공유 DB로 전환해야 한다.
   - 현재 연결 변경은 아직 커밋·푸시 전이므로 기존 PR #11만 받은 팀원에게 자동 전달되지 않는다.

## 우선순위

1. catalog FastAPI/DB 원본을 관리자·상품 화면·주문 담당자가 함께 읽도록 통합
2. 품절 판정 필드와 주문 시 검증을 영우 담당자와 확정
3. 신규 상품의 농가·채소 참조 및 농가 고정 ID 연결 보완
4. 이벤트 편집 후 기존 상세 기능·쿠폰 정책의 분리 또는 통합 방침 확정
5. 저장 성공 안내 시점과 두 브라우저 자동 갱신 실측
