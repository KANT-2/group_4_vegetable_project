# 레시피 인기 순위·보관 손질법 — 2026-10-27

## 적용 화면

- `/recipes` 검색 폼 바로 위에 실시간 인기 레시피 TOP 3를 표시한다.
- 제목·순위 영역에만 연한 주황 배경을 적용하고, 오른쪽 보관·손질법 버튼은 흰 배경에 둔다.
- 순위마다 작은 요리 사진·요리명·조회 횟수를 표시한다. 시간 범위 안내 문구는 화면에 추가하지 않았다.
- 버튼을 누르면 중앙 채소 선택 모달이 열린다. 감자·당근·양파·애호박·브로콜리·양배추를 먼저 배치하고 나머지 채소까지 21종을 스크롤해 고른다.
- 채소 선택 시 `/vegetables/{id}`로 이동해 사진·이름이 있는 페이지 맨 위부터 보여 준다. 보관·손질법은 그 아래에서 확인한다. X·Esc로 닫을 수 있다.

## 실제 조회 집계

- 레시피 상세의 클라이언트가 화면에 표시될 때만 POST한다. Next.js 링크 프리패치·빌드에서는 집계하지 않는다.
- Next.js는 같은 출처 요청인지, 레시피가 현재 카탈로그에 존재하는지 확인한다.
- 30일 HttpOnly·SameSite=Lax 익명 UUID 쿠키로 같은 브라우저를 식별한다. 집계 테이블에는 이메일·IP·회원 ID를 저장하지 않는다.
- `(recipe_id, visitor_id, viewed_hour)` 고유 키로 같은 브라우저·같은 요리·같은 시간대의 중복 새로고침을 막는다. 시간대는 서버 기준 시각의 정각 단위다(직전 조회 후 정확히 60분 경과 방식은 아님).
- 최근 24시간 이벤트 수 내림차순, 동률은 ID 순서로 최대 3개를 표시한다. 따라서 전체 누적 조회수나 고유 방문자 수와 다르다.
- 30초마다, 그리고 탭이 다시 보일 때 순위를 갱신한다. 백그라운드 탭에서는 조회를 줄인다.
- 집계가 없으면 빈 상태, 서버 장애 시 조회 실패 안내를 표시한다. 가짜 순위 숫자를 채우지 않으며 상세 조회 이용은 집계 실패로 막지 않는다.

## API·DB

- Next.js `GET /api/recipe-rankings`, `POST /api/recipe-views`.
- FastAPI `GET·POST /api/v1/catalog/recipe-views`.
- `supabase/migrations/202610270001_recipe_views.sql`: 익명 집계 테이블·고유 키·최근 시각 인덱스·RLS 및 anon/authenticated 직접 접근 차단. 현재 팀 DB에 적용했다.
- 레시피는 DB·파일·관리자 콘텐츠를 합쳐 제공하므로 recipes 테이블에 외래키를 걸지 않는다. 공개 화면에는 현재 레시피 카탈로그와 일치하는 ID만 표시한다.
- 팀원이 코드를 받을 때 백엔드 재시작이 필요하다. 다른 DB 환경에는 새 마이그레이션도 적용해야 한다.
