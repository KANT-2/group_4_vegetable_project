# C 장바구니·찜 통합 및 공통 저장 버튼

작업일: 2026-10-12 / 담당: C 이상재.

## 구현

- `/cart`: 장바구니·찜 탭(`/cart?tab=wishlist`). 로그인하지 않으면 로그인 후 같은 탭으로 돌아옵니다.
- 장바구니: 수량 수정(1~99), 삭제, 상품 금액(정가)·못난이 할인·결제 예정 금액 합계, 빈 상태 안내. 판매가 끝난 상품은 표시만 하고 합계에서 뺍니다.
- 찜: 목록, 장바구니 1개 담기, 찜 해제, 빈 상태 안내.
- 공통 버튼(`src/components/shopping`): `AddToCartButton`(수량 선택 + 담기), `WishlistButton`(♡/♥), `QuantityStepper`. 상품 상세의 "준비 중" 버튼을 교체했습니다. 모바일은 하단 고정 바에 찜·수량·담기를 한 줄로 둡니다.
- 서버 처리(`src/actions/cart.ts`): 같은 상품을 다시 담으면 수량을 더하고 99개를 넘지 않습니다. 동시에 담아 생기는 중복(23505)은 기존 줄에 더합니다. 찜 중복 클릭은 성공으로 처리합니다.
- 로그인 복귀: 로그인 전에 담기·찜을 누르면 `/login?next=<보던 화면>`으로 이동합니다.
- 헤더 장바구니 숫자는 담기·수정·삭제 후 다시 조회합니다.
- 주문하기 버튼은 주문·모의 결제 화면이 생기면 연결합니다.

## 권한

- 수정 대상 사용자는 서버에서 확인한 로그인 사용자로만 정합니다. 입력에 다른 필드(`user_id` 등)가 있으면 거부합니다.
- 기존 RLS(`cart_*_own`, `wishlist_*_own`)를 그대로 사용합니다. DB 변경은 없습니다.

## 검증

- 테스트 30개 통과: 새로 담기·수량 더하기·99개 제한, 판매 종료·잘못된 수량·비로그인 거부, 다른 사용자 줄은 바뀌지 않음, 찜 중복 처리, 합계·할인 계산.
- 타입·lint·포맷 검사 통과.
- 로컬에서 비로그인 담기 → `/login?next=/products/...` 이동 확인. 360px·375px 하단 바 가로 넘침 없음 확인.
- 로그인 상태의 실제 담기·수량·삭제·찜은 배포 후 화면에서 추가 확인합니다.
