# 주문·모의 결제

장바구니 → `/cart/checkout` → 배송지 확인 → 모의 성공/실패 → 주문 상세로 이동합니다. 실제 결제·배송은 하지 않으며 카드번호를 수집하지 않습니다. 배송비는 모의 주문에서 0원입니다.

## DB 적용

기존 migration을 순서대로 적용한 뒤 `supabase/migrations/202610120003_mock_checkout.sql`을 적용합니다. 기본 배송지와 환불 테이블 migration도 먼저 적용되어 있어야 합니다.

`mock_checkout` RPC만 로그인 사용자에게 실행 권한을 부여합니다. `orders`, `order_items`의 직접 쓰기 권한은 열지 않습니다. 함수는 `auth.uid()`로 계정을 결정하고 DB의 판매 상태·가격·수량을 확인합니다. 화면에서 본 상품/수량/가격과 달라지면 저장을 취소합니다.

동일 계정·request_key의 재전송에는 기존 주문을 반환합니다. 최초 요청 결과가 실패였다면 성공으로 변경하지 않습니다. 실패 후 장바구니에서 새 주문을 시작하면 새로운 키가 발급됩니다. 성공하면 주문 상품만 장바구니에서 제거하고, 실패하면 유지합니다. 주문 당시 상품명·단위·가격·배송지는 별도 저장되어 이후 수정에 영향을 받지 않습니다. 화면에서 바꾼 배송지는 기본 배송지를 덮어쓰지 않습니다.

## 검증

`npm test`의 PGlite 검증: 비로그인 차단, 빈 장바구니·위조 가격·잘못된 배송지 거절, 실패 시 장바구니 유지, 성공 시 금액·상세 저장 및 장바구니 정리, 중복 재전송, 계정 분리.

2026-10-12 공용 `vegetable` DB에 migration을 적용하고 실행 권한을 확인했습니다. localhost의 로그인 계정에서 가상 배송지로 25,800원 주문을 실패/성공 각각 1건 생성했습니다. 실패 시 상품 2개 유지, 성공 시 장바구니 비움 및 주문 상세·환불 링크를 확인했습니다. 테스트 후 기존 장바구니 상품 2개를 복원했습니다. 테스트 주문 2건은 삭제하지 않고 모의 주문 기록으로 남겼습니다. 배포 사이트 검증·물리적 모바일 입력 검수는 아직 진행하지 않았습니다. 실제 결제 도입 시에는 클라이언트가 선택하는 성공/실패 대신 결제 업체가 검증한 결과와 웹훅으로 상태를 결정해야 합니다.
