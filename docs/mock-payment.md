# 주문·모의 결제

장바구니 → `/cart/checkout` → 배송지 확인 → 주문하기 → 주문 상세로 이동합니다. 신용·체크카드 / 계좌이체 / 간편결제 중 결제 수단을 선택하고 주문하기를 누르면 모의 결제 성공으로 처리합니다. 선택한 수단은 주문 상세에 표시합니다. 화면의 실패 시연 버튼과 버튼 위 안내 문구는 제거했습니다. 실제 결제·배송은 하지 않으며 카드번호를 수집하지 않습니다. 배송비는 할인 후 상품 합계 20,000원 이상이면 0원, 미만이면 3,500원입니다.

## DB 적용

기존 migration을 순서대로 적용한 뒤 `supabase/migrations/202610120003_mock_checkout.sql`을 적용합니다. 기본 배송지와 환불 테이블 migration도 먼저 적용되어 있어야 합니다. 그 다음 `202610120004_order_payment_method.sql`로 orders.payment_method와 기존 함수의 저장 로직을 추가합니다. 새 실행 권한은 추가하지 않습니다. 기존 주문은 결제 수단을 추정해 채우지 않고 NULL로 유지하며 상세에서 기록 없음으로 표시합니다. 이전 버전 앱에서 수단을 생략한 새 주문은 호환성을 위해 card로 저장합니다.

`mock_checkout` RPC만 로그인 사용자에게 실행 권한을 부여합니다. `orders`, `order_items`의 직접 쓰기 권한은 열지 않습니다. 함수는 `auth.uid()`로 계정을 결정하고 DB의 판매 상태·가격·수량을 확인합니다. 화면에서 본 상품/수량/가격과 달라지면 저장을 취소합니다.

동일 계정·request_key의 재전송에는 기존 주문을 반환합니다. 최초 요청 결과가 실패였다면 성공으로 변경하지 않습니다. 실패 후 장바구니에서 새 주문을 시작하면 새로운 키가 발급됩니다. 성공하면 주문 상품만 장바구니에서 제거하고, 실패하면 유지합니다. 주문 당시 상품명·단위·가격·배송지는 별도 저장되어 이후 수정에 영향을 받지 않습니다. 화면에서 바꾼 배송지는 기본 배송지를 덮어쓰지 않습니다.

## 검증

`npm test`의 PGlite 검증: 비로그인 차단, 빈 장바구니·위조 가격·잘못된 배송지 거절, 실패 시 장바구니 유지, 성공 시 금액·상세 저장 및 장바구니 정리, 중복 재전송, 계정 분리.

2026-10-12 공용 `vegetable` DB에 migration을 적용하고 실행 권한을 확인했습니다. localhost의 로그인 계정에서 가상 배송지로 25,800원 주문을 실패/성공 각각 1건 생성했습니다. 실패 시 상품 2개 유지, 성공 시 장바구니 비움 및 주문 상세·환불 링크를 확인했습니다. 테스트 후 기존 장바구니 상품 2개를 복원했습니다. 테스트 주문 2건은 삭제하지 않고 모의 주문 기록으로 남겼습니다. 배포 사이트 검증·물리적 모바일 입력 검수는 아직 진행하지 않았습니다. 실제 결제 도입 시에는 클라이언트가 선택하는 성공/실패 대신 결제 업체가 검증한 결과와 웹훅으로 상태를 결정해야 합니다.

## 결제 수단 확장 — 2026-10-12

공용 DB에 `202610120004_order_payment_method.sql` 적용 완료. 가상 배송지로 계좌이체 20,700원 주문을 저장하고 주문 상세·새로고침 후에도 수단이 유지되는 것을 확인했습니다. 검증 후 기존 장바구니 표고버섯 3개를 복원했습니다. 실제 계좌번호·카드번호는 수집하지 않으며 테스트 주문은 기록으로 유지합니다.

결제 화면 제목은 ‘결제’, 배송비에는 ‘모의 주문’ 문구를 표시하지 않습니다. 상세주소는 결제 시 필수이며 클라이언트·Server Action·DB 함수에서 공백만 있는 값을 거절합니다. `202610120005_required_checkout_address_detail.sql`을 마지막에 적용합니다. 기본 배송지를 관리하는 마이페이지의 선택 입력과 기존 주문 데이터는 유지합니다.

## 배송비 정책

`202610120006_order_shipping_fee.sql`을 적용합니다. 상품 판매가 × 수량의 합계로 무료배송 기준을 판단합니다. 화면·장바구니 예상 금액과 DB 주문 함수가 동일한 20,000원 기준을 사용합니다. DB가 배송비를 계산하므로 요청에서 0원을 주입해도 적용되지 않습니다. total_amount는 배송비 포함 최종 금액, shipping_fee는 주문 당시 배송비입니다. 기존 주문의 총액과 배송비 0원은 유지합니다. 주문 상세에서 상품 금액·배송비·최종 금액을 구분합니다.

2026-10-12 공용 DB 적용 완료. 가상 배송지로 표고버섯 2개(13,800원) 주문에 배송비 3,500원이 합산되어 총 17,300원으로 저장·표시되는 것을 확인했습니다. 검증 후 장바구니를 원래 표고버섯 3개로 복원했습니다. 테스트 주문은 모의 주문 기록으로 유지합니다.
